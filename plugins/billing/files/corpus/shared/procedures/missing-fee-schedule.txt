Procedure: Missing fee schedule

Applies to billing runs that fail with the failure code FS-REQUIRED, meaning one or more billable accounts could not resolve a fee schedule for the billing period.

Section 1: Preparation
1. Open the failed billing run and confirm the failure reason starts with "FS-REQUIRED".
   The description states how many accounts are affected, for example "fee schedule missing for 3 accounts".
2. Confirm you have the OPS or FIRM_ADMIN role for the firm.
   Only a FIRM_ADMIN can create a new fee schedule; OPS can assign existing schedules.
3. Note the run id, the period start and period end dates, and the valuation date for your records.

Section 2: Identify affected accounts
1. Open the run diagnostics and filter by the code FS-REQUIRED to list the accounts without a schedule.
2. For each account, check whether it belongs to a household.
   If the household has a schedule, the account may have an override that points to a retired schedule.
3. Check the account opening date and the advisory agreement to determine which schedule the client agreed to.
4. If the correct schedule cannot be determined from the agreement, ask the servicing advisor before continuing.

Section 3: Assign a fee schedule
1. Assign the agreed fee schedule to each affected account, or to its household if all members share the schedule.
   Set the effective date on or before the period start so the whole period is covered.
2. If the agreed schedule does not exist in the catalog, ask a FIRM_ADMIN to create it before assigning it.
3. Record the reason for the assignment in the change note, referencing the failed run id.

Section 4: Validate
1. Run the schedule validation check for the period from the billing run page.
   The check must report zero accounts without a schedule.
2. Confirm the new assignments do not overlap existing ones, which would cause a PRORATION-GAP failure.
3. Spot-check the estimated fee for at least one affected account against the agreement.

Section 5: Re-run
1. Request a re-run of the failed billing run; the status moves from failed back to pending.
2. Monitor the run until it reaches completed, and confirm the affected accounts now show a calculated fee.
3. If the run fails again, read the new failure reason and follow the matching procedure.
