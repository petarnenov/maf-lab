# Proposal

## Why

`make index` fails whenever the compose stack is not running — after `make down`, after a reboot, or on a fresh
checkout before the first `make`. The indexer is a host-side CLI that needs Qdrant (6333/6334) and the compose Ollama
(11435, the embedding model), but no index target starts them, so the run dies on its first Qdrant call with an
unhandled `Grpc.Core.RpcException: Status(StatusCode="Unavailable", … Connection refused)`, a .NET stack trace and
`make: *** [Makefile:129: index] Aborted (core dumped)`. Nothing in that output tells the developer what to do. The
same holds for `index-portfolio`, `index-code`, `reindex`, `drift`, `rebuild-index` and `migrate`. It must work the
same on macOS (GNU Make 3.81, bash 3.2, Docker Desktop) and Linux.

## What Changes

- A new `make infra` target starts only what the indexer needs — `qdrant`, `ollama`, and `ollama-init` (pulls the
  embedding model when it is missing) — and waits until they are healthy. On a running stack it is a no-op that
  finishes in about a second; it never starts, stops or rebuilds the application services.
- `index`, `index-portfolio`, `index-code`, `reindex`, `drift`, `rebuild-index` and `migrate` depend on `infra`, so
  each works from a stopped stack.
- The indexer CLI turns an unreachable Qdrant or Ollama into one actionable line on stderr (which service, which
  address, "run `make infra`") and exit code 1, instead of an unhandled exception and a core dump. The progress bar
  still ends in its failure line naming the exception type only.
- Portability: the target uses only `docker compose` flags available in Docker Desktop for macOS and Docker Engine on
  Linux (`up -d --wait`), and Make 3.81 syntax; no GNU-only shell or `sed` features.

Progress feedback: `make infra` shows compose's own per-service progress (each container's state and elapsed time
while it waits for health) and `ollama pull`'s download bar when the model is missing; the indexer keeps its existing
progress bar, now ending in the failure line before the actionable message.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `make-workflow`: a new requirement — the indexer targets start the infrastructure they need (`make infra`) and work
  from a stopped stack, on macOS and Linux. `infra` is listed by `make help` under the existing catalogue rule.
- `document-indexing`: a new requirement — an unreachable Qdrant or Ollama ends the run in an actionable one-line
  message and a non-zero exit, never an unhandled exception.

## Impact

- `Makefile` — new `infra` target; `infra` added as a prerequisite of the seven indexer targets and to `.PHONY`.
- `src/Maf.Lab.Indexing/Program.cs` — catch connection failures to Qdrant (gRPC `Unavailable`) and Ollama
  (`HttpRequestException`) and print the actionable message; exit 1.
- `tests/` — a unit test for the message mapping (which service, which address, no exception message text).
- No package version moves; no compose change.

## Documentation impact

- `README.md` — the generated make-target list gains `infra` (regenerated by `make docs` from the Makefile
  descriptions). No hand-written README text claims `make index` needs a running stack.
- `openspec/project.md`, `.github/copilot-instructions.md` — their generated command blocks gain `infra` if they list
  make targets (regenerated by `make docs`).
- `CLAUDE.md` — its command list names `make index`; it stays true (now works from a stopped stack), no edit needed.
