# Proposal

## Why

`progress-feedback` says every proposal that adds or alters a CLI tool, a `make` target or a UI action longer than
3 seconds must say how it shows progress — but, as `stop-anything` was until `check-stop-in-proposals`, only review
enforces it. Both rules are top priority in this project and belong together: the person sees the work moving, and
can stop it when it costs them and they no longer want it. The build should fail a proposal that says neither.

## What Changes

- `make docs-check` checks every active change's `proposal.md` for a `## Progress` section, and fails, naming the change
  and the reason, when the section is missing or empty, or says none of what it may say:
  - **None:** `None — <reason>`: the change adds or alters no CLI tool, `make` target or UI action that can run longer
    than 3 seconds;
  - **How it shows:** at least one of `Terminal:` (the progress bar a CLI tool or `make` target shows) and `Page:` (the
    themed progress the page shows), each one given with a value;
  - **Not yet:** `Not yet — <reason>; follow-up: <change>` — the rule allows a change that cannot meet it, if it says why
    and names the change that will.
- The labelled-line parsing the `## Stopping` check uses becomes one helper both checks share, so the two sections read
  the same way (list items, bold labels, continuation lines, HTML comments not counted).
- `openspec/config.yaml`'s proposal rule for progress says to write the section, in that shape.
- As with `## Stopping`, the check makes sure it was said; whether it is right stays review's call.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `documentation-sync`: "The documentation check" adds the `## Progress` rule beside the `## Stopping` one.
- `progress-feedback`: "Changes are checked against the rule" — the section is how a proposal says it, including the
  allowed "not yet, with a follow-up", and `make docs-check` fails a proposal that does not.

## Impact

- `scripts/docs.py` (`check_change_proposals`, the shared labelled-line reader), `scripts/tests/test_docs.py`,
  `openspec/config.yaml` (`rules.proposal`).
- No product code, route or target; `make docs-check` already runs in CI.
- Active changes: only this one, which carries the section.

## Progress

None — this change adds no CLI tool, `make` target or UI action: it adds a rule to a check that ends in moments.

## Stopping

None — this change adds no work a person can start: it adds a rule to a check that ends in moments.

## Documentation impact

- `CLAUDE.md`: the progress-feedback non-negotiable says `make docs-check` enforces the `## Progress` section.
- `openspec/project.md`: the "Progress feedback" convention says the same (its copy in `openspec/config.yaml` is
  regenerated by `make docs`).
- `.github/copilot-instructions.md`: the same sentence in its progress rule.
