# Proposal

## Why

Long work in this repository is often silent: a `make` target, an indexer or
an eval run can sit for minutes with no sign of how far it got, and a button
in the UI can start a job that looks frozen after a couple of seconds. People
then cancel healthy work, or wait on work that has stalled. Progress feedback
is a project-wide rule, not a per-feature nicety, so it belongs in the
conventions every change is checked against.

## What Changes

- Add a top-priority convention to `openspec/project.md`: **every CLI tool
  shows a progress bar for the work it does, and every process started from
  the UI that can take longer than 3 seconds shows progress that matches the
  page's theme and design.**
- Add a new capability spec, `progress-feedback`, that states what "a
  progress bar" and "progress that matches the page" mean, so the rule is
  testable: determinate when the total is known, indeterminate otherwise,
  a quiet form when output is not a terminal, theme tokens in the UI, an
  accessible `progressbar` role, and an end state for success, failure and
  cancel.
- Add a proposal rule to `openspec/config.yaml` so every future proposal
  that adds or changes a CLI tool or a UI-started process says how it shows
  progress.
- Repeat the rule in `CLAUDE.md` (non-negotiables) and
  `.github/copilot-instructions.md` (key conventions), so every agent that
  edits the repository sees it.
- Existing tools and screens that do not meet the rule yet are listed in
  `design.md` as known gaps; each is brought into line by its own follow-up
  change. No runtime code changes in this change.

## Capabilities

### New Capabilities
- `progress-feedback`: the project-wide rule for progress on CLI tools and
  on UI-started processes longer than 3 seconds — what counts as progress,
  its terminal and non-terminal forms, its themed UI form, accessibility, and
  its end states.

## Impact

- Documents: `openspec/project.md`, `openspec/config.yaml` (its
  `project-context` block is regenerated by `make docs`), `CLAUDE.md`,
  `.github/copilot-instructions.md`.
- Future work: every change that adds or alters a CLI tool (console apps
  under `src/` and `tools/`, `scripts/*`, `make` targets) or a UI action that
  starts a long process (`web/src`) must meet `progress-feedback`.
- No code, API, dependency or model changes.

## Documentation impact

- `openspec/project.md` — new "Progress feedback" convention (the source of
  the rule).
- `openspec/config.yaml` — `project-context` regenerated from project.md by
  `make docs`; new `rules.proposal` entry.
- `CLAUDE.md` — new non-negotiable line with the rule.
- `.github/copilot-instructions.md` — new key-convention bullet with the rule.
- `README.md` and `docs/*.md` — not affected: they describe features, not
  project conventions.
